## 2. Подтверждённые контрольные меры (хорошо)

- bcrypt-хеши паролей, JWT HS256 с `aud`/`iat`/`exp`, проверка `is_active` на каждом запросе.
- Upload: whitelist расширений + magic-bytes + лимит 20 МБ + ≤10 файлов; имя файла через `.name` (без трэверсала на запись).
- Парсеры: PDF→pdfplumber/PyMuPDF, RTF→striprtf, ODT→ElementTree (внешние сущности не резолвит) — без небезопасных вызовов.
- В коде нет `subprocess`/`os.system`/`eval`/`pickle`/`yaml.load`/`shell=True`.
- Внешние API (NVD/BDU/CMDB): таймауты ограничены, ретраи ≤3, ошибки → graceful в `external_errors`, кэш в Redis.
- Секретов/`.env` в git нет (`.env*` в `.gitignore`), bootstrap-пароль — одноразовый.
- CORS `allow_origins=["*"]` без `allow_credentials` — не усиливает атаки (Bearer-заголовок).

## 3. Открытые рекомендации (деплой/прод)

| # | Рекомендация | Приоритет |
|---|--------------|-----------|
| P1 | Задать `FSTEC_SECRET_KEY` (длинный случайный) в прод-окружении | Высокий |
| P2 | Redis: `requirepass` + `bind` на внутренний интерфейс; в docker-compose убрать `127.0.0.1:6379` наружу при деплое | Высокий |
| P3 | Проверка принадлежности документа пользователю: `/documents/*`, `/reports/*/download*`, `/reply/generate`, `/api/letters/*` читают по `doc_id` без owner-фильтра (для мульти-операторского режима) | Средний (внутренняя система — низкий) |
| P4 | Внешние интеграции (BDU/NVD/CMDB) в прод-контуре с доверенными корневыми сертификатами, без `verify=False` | Средний |
| P5 | Kafka/AI-шина между сервисами: аутентификация/ACL (сейчас внутренняя сеть) | Средний (если не изолированная сеть) |

## 5. Примечание для локального e2e-контура

На этой машине TLS к `bdu.fstec.ru` не проходит проверку (перехват/прокси), поэтому для локальных прогонов, где нужно живое BDU-обогащение, задавайте явно:
`FSTEC_BDU_INSECURE_FALLBACK=1`. В проде флаг должен оставаться `0`.
