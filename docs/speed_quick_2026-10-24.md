## Что ускорять без потери качества

1. **Кэш по SHA-256 исходника** — повторный файл не гонять через LLM/BDU; качество идентично, экономия до 100% на дублях.
2. **Не вызывать `plan_reply`, если сработал reference-профиль** — ответ уже детерминированный (98.3%);
   включать только для незнакомых писем, с A/B на 22 эталонах.
3. **Объединить analyze + extract IoC** (если ещё не merged) — минус один LLM-вызов; сравнить качество на корпусе.
4. **Ограничить `max_tokens` для plan_reply** и убрать reasoning; проверять метрики, а не «на глаз».
5. **Прогрев и keep-alive** уже работают (0.1 с); не трогать.
6. **Аппаратно/батчинг**: поднять `max-num-seqs`/GPU после того, как п.1–4 дадут запас по качеству.

Порядок: сначала кэш и отказ от лишнего `plan_reply` (нулевой риск для качества), затем merged analyze,
затем аппаратные настройки. Любое изменение — только с прогоном `glpi_run28`-метрик (98%+ и меры 551/551).
